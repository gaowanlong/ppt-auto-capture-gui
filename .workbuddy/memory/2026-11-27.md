# 2026-11-27

## v2.16.0 — 鸿蒙电脑（HarmonyOS PC / 2in1）版本工程

- 用户选择路线：**ArkUI + Rust NAPI 核心**（不是 winit-ohos 复用 egui，也不是 Tauri）；有真机，**没有签名证书**，只能做可调试 HAP 与验证步骤。
- 调研事实（2026-11 联网确认）：
  - 三方应用全屏截图权限是 `ohos.permission.CUSTOM_SCREEN_CAPTURE`，user_grant，API 14+，仅平板/2in1；`module.json5` 需 reason/usedScene。
  - 静默检查用 `bundleManager.getBundleInfoForSelfSync` + `checkAccessTokenSync`；申请必须前台 `requestPermissionsFromUser`。
  - `@ohos.screenshot.capture({displayId})` 在 PC/2in1 可用，返回 PixelMap；`pick()` 免权限但仅主屏区域。
  - 应用沙箱：`context.filesDir`；用户目录必须 `DocumentViewPicker` + `fileShare.persistPermission`，Picker URI 不可手工拼接。
  - winit-ohos 0.31.0-beta.3 存在但依赖 winit-core beta + git fork，Rust 1.88+；用户没选这条。
- 实现：
  - `ohos/rust_core`：独立 crate，`#[path]` 复用 `src/{pptx,detection,storage,model}`，**不复制源码**；`engine.rs` 复刻桌面 process_frame 状态机；`napi_bridge.rs` 导出 `OhosSession` / `openSession` / `recoverSession` / `trimDeck`，显式 js_name 固定 camelCase。
  - host 测试 168 通过；`cargo check --target aarch64-unknown-linux-ohos` 通过（rustup 已装该 target）。
  - `ohos/entry/src/main/ets`：Index.ets 四页卡片 UI（Record/Settings/Appearance/Create PPTX）、Capture.ets（screenshot 采样 + 最小化窗口）、Permissions.ets、Files.ets（沙箱/选择器/持久化/导出）、NativeBridge.ets + native.d.ts。
  - `scripts/build-ohos.sh`：按主机选 SDK/native 目录，设置 linker/sysroot，编译 .so 到 `libs/arm64-v8a/`，有 hvigorw 才打 HAP。
- 坑与注意：
  - `napi-ohos` 1.2 的 `#[napi(constructor)]` 必须返回 Self，不能返回 Result；改成存 `init_error` 字符串暴露给 UI。Uint8Array 从 `napi_ohos::bindgen_prelude` 导入。
  - 复用 `#[path]` 模块时，`pptx` 的测试用 quick_xml、image 需要 jpeg/bmp/webp feature，否则 host 测试编译失败。
  - 没有 DevEco/hvigorw/签名证书，ArkTS 与 HAP **未真机编译验证**；README 写了 6 步真机验收清单。
- 未打 tag / 未发 Release：HAP 无签名不能交付，桌面 2.16.0 单独发会误导；等用户确认或拿到签名后再决定。
