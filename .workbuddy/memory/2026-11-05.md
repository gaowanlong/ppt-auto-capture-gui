
## v2.12.0 — 裁剪入口收敛到 pptx→pptx + 深色幻灯片修复

- 需求：录制场景彻底不要裁剪；裁剪勾选项只在「输入 pptx → 输出 pptx」出现；同时验证裁剪功能。
- 删除范围：`OutputPanel.auto_crop`、`CaptureSource.auto_crop`、`SessionStore::set_auto_crop` 与日志字段、`import_directory(..., auto_crop)` 参数、`PptxWriter::with_auto_crop` + `build_frame_reference` + 写入时的检测分支、`t_auto_crop_*`/`t_export_crop_*` 文案。旧配置/旧日志里的 `auto_crop` 键由 serde 忽略（config.rs 保留一条兼容测试）。
- 新增：`ExportPanel.crop_enabled`（默认 true）+ `can_start()`；deck 页勾选项「裁剪 PPTX 中截图的边缘」，未勾选时按钮禁用、摆放方式隐藏，`start_deck` 里也有守卫。
- 验证手段：临时 `examples/{pptx/mod.rs, deck_verify.rs, img_probe.rs, support/storage.rs}`（`#[path]` 挂 src 模块；`crate::storage` 需垫片，垫片不能直接放 examples/ 否则被当成 example target，放 `examples/support/`）+ python-pptx/Pillow 合成会议截图。用完即删。
- 发现并修掉两个真 bug：
  1. 深色幻灯片 + 深色界面整张不裁：`bright<2%` 走 `detect_edge_fallback`，它在 `has_chrome_border` 前只做 letterbox/static，没做 `trim_dark_area_edges` + `trim_stable_chrome_edges`，于是右侧面板/底部工具栏留在候选框里 → 判定不通过 → None。补上两步后 1512×982 → 1273×716，近黑 27.9% → 1.2%。
  2. 全页铺满的图片裁完几何不变，`cropped` 计数为 0，界面显示「都不需要裁剪」。改为按「媒体是否被写入 staging」计数。
  3. 顺带：无候选图片时的报错区分「没有图片」/「有图片但都不是截图」。
- 结论（写进交付说明）：白底 26.0% → 0.0%；深底 27.9% → 1.2%；满屏演示文稿、小图标、已带 srcRect 的图片保持原样；二次裁剪字节不变；源文件哈希不变。
- 遗留：满屏照片/图表类（几乎没有成片白色背景、又不满足 `bright<2%`）不走兜底，仍整图保留；白底工具栏故意不裁。
- 网络：7890 代理当时没开，git 全局配了该代理 → 改用 `git push git@github.com:... main` 走 SSH 推送；`gh` 用服务代理正常。
