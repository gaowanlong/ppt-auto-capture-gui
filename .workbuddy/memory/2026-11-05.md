## v2.13.0 — 手动删截图导致录制停不下来

- 现象：录制中在 `sessions/<id>/slides/` 删掉重复截图后，停止报
  `Session finalization failed: Failed to read PNG …`，状态卡在 Paused；
  「停止并保留截图」也走 `checkpoint_for_recovery()` 的同一套文件检查，被一起堵死。
- 根因：`SessionStore::finish()` → `publish()` → `PptxWriter::write_slides()` 逐条记录读 PNG，
  一条缺失就整体失败；`checkpoint_for_recovery()` 缺文件直接 `ensure!` 失败。
- 修法（`src/storage/session.rs`）：
  - 新增 `PublishReport { published, skipped, decks }`；`finish()/recover()/publish()` 返回它。
  - `screenshot_readable()` 做廉价完整性探测：PNG 8 字节签名 + 末尾含 `IEND`（seek End(-8)，
    取前 4 字节比较，别写成比较整个 8 字节——IEND 后还有 4 字节 CRC）。
  - `publish_part()` 先筛掉不可读页，再按 1..n 重编号写盘；全空则跳过写盘、不报错。
  - `checkpoint_for_recovery()` 缺文件只 `warn!`，不再失败。
  - `output_paths()` 删除（已无调用者），恢复路径改用 `report.decks` 只报真正写出的分段。
- 事件：新增 `WorkerEvent::SlidesSkipped(usize)`；app 记 `DiagnosticLevel::Warning`（活动记录），
  不占用顶部红色错误条；文案 `i18n::t_slides_skipped`。
- 测试（314 通过）：删中间页后成稿 2 页、skip=1；空文件/截断文件 skip；删页后 preserve 仍可完成；
  recovery 跳过删除页且不动旧成稿。
- 教训：写测试造不同页时用色差大的像素（10 vs 200），差 1 会被 `MotionFilter` 当重复丢掉。

## v2.14.0 — 跳过 PPT 过渡动画

- 现象：平滑（Morph）/推入/擦除/淡入等过渡会被截成 2–3 张画到一半的页面进成稿。
- 根因：`process_frame` 的「快速翻页」分支里有一层 *参考帧兜底*——只要进入 WaitingForStable 后
  又检测到变化，就把 `change_detector` 的上一帧保存。过渡动画每 500ms 采样都不同，于是每帧都
  触发一次兜底保存。
- 修法（`src/capture/capture_worker.rs`）：
  - 删掉参考帧兜底，只保留 `stability_detector.get_pending_frame()`（stable_count > 0，即上一帧
    已静止至少一个采样周期）的补存。判据变成「至少安静过一个采样」才算真实页面。
  - 黑场恢复不再立即保存：改为进入 WaitingForStable（reset + timer + update_reference +
    `first_frame_saved = true`），让稳定块保存最终画面（黑场淡入的第一帧通常是半成品）。
  - `finish_session()` 先补存已静止的 pending 帧，再生成 PPTX（稳定窗口内点停止不丢当前页）。
  - `ChangeDetector::get_reference_frame` 删除；`report_rapid_transition_save_failure` 改名
    `report_settled_frame_save_failure`，文案 `Settled slide save failed: …`。
- 语义变化：只被单次采样带过的页面（<1 个采样周期）现在按过渡帧跳过。这正是 README 原有
  「intermediate pages held for multiple samples retain their capture path」的字面含义。
- 测试（316 通过）：morph 5 个中间帧都不入稿、黑场淡入只存最终帧、稳定窗口内停止保留当前页、
  单采样页面按过渡跳过；`broad_rapid_slide_changes_keep_intermediate_pages` 改名并改为断言跳过。
- 坑：`MotionFilter::differs` 用 >20 的通道差，测试造帧时 200 vs 210 会被当成重复页丢掉。

## v2.15.0 — 配置文件改到用户目录（修 macOS 设置存不下）

- 根因：`AppConfig::save()` 用相对路径 `ppt-auto-capture-config.json` 写配置，启动不调整 cwd。
  macOS 从访达/启动台打开 .app 时 cwd 是 `/`，写入失败 → 外观/语言/输出目录重启即丢，
  点开始报 `Unable to save recording settings for recovery`。Windows 双击 exe 时 cwd=exe 目录，所以那边正常。
- 修法（`src/config.rs`）：
  - `config_directory(os, home, appdata, xdg, cwd)` 纯函数决定目录：macOS `~/Library/Application Support/PPT Auto Capture/`、
    Windows `%APPDATA%\PPT Auto Capture\`、其他 `$XDG_CONFIG_HOME` 或 `~/.config/` 下 `ppt-auto-capture/`；
    都拿不到时**退回 cwd**（保持旧行为，不因取不到路径就拒绝保存）。
  - `AppConfig::path()`（绝对路径）；`read(path)` / `save_to(path)` 拆出可测版本；`save()` 自动 `create_dir_all`。
  - `load()` → `load_migrating(current, legacy)`：先读新位置，没有再读 cwd 里的旧文件并 `save_to` 复制过去（旧文件保留不删）。
  - `load()` 里 `info!("Settings file: ...")`，以后看日志就知道实际用了哪个文件。
- 端到端验证（真机 debug 二进制 + 临时 HOME）：
  - cwd 里放一份 `stability_frames=7 / Chinese / Dark` 的旧配置，`HOME=/tmp/...` 启动 6 秒后杀掉，
    新目录出现 `Library/Application Support/PPT Auto Capture/ppt-auto-capture-config.json` 且值一致 → 迁移有效。
  - `cd /` + 临时 HOME 启动：日志打印新路径，根目录没有生成配置文件 → 不再依赖启动目录。
- 测试 324 通过（新增 6 个）；clippy 39 条 → 基线从 40 下调到 39（CI 会要求同步下调）。
- README 里「配置写在 working directory」那句改成三平台实际路径 + 旧文件迁移说明。
