# 2026-11-02

## 项目：ppt-capture（ppt-auto-capture-gui）

- 克隆 `https://github.com/gaowanlong/ppt-auto-capture-gui`，v2.7.5 基线。Rust + eframe/egui 桌面工具：自动截取演示画面，停止后生成 PPTX。
- 结构要点：
  - `src/pptx/pptx_writer.rs` 从零构建 PPTX（ZIP + 手写 OOXML），`slide_xml.rs` 生成 slide XML。
  - `src/pptx/crop.rs`（2788 行）是裁剪算法核心：`detect_presentation_with_reference(&DynamicImage, Option<&FrameReference>) -> Option<(x,y,w,h)>`，`FrameReference::from_scaled_images` 用多帧对比识别静态任务栏/会议控件。均为 `pub(super)`。
  - `src/gui/export_panel.rs`「图片转 PPTX」页；`src/storage/import.rs` 图片目录 → PPTX。
  - 质量门禁：`cargo test --all-targets`、`scripts/check-clippy-baseline.sh`（基线 40，Linux CI 计数）、`scripts/check-rustfmt-changed.sh`、`tests/*.sh|rb` 契约测试。
  - 发版：推 `v*` tag 触发 `.github/workflows/build-release.yml`，产出 Windows exe / Linux tar.gz / macOS arm64 dmg。

### 本次新增（v2.8.0）
- 新增 `src/pptx/deck_crop.rs`：读取已有 PPTX（presentation.xml 顺序 → rels → p:pic 的 a:off/a:ext），复用裁剪检测，重写媒体部件并调整图片几何；其余部件逐字节复制，源文件只读。
- 判定规则：图片覆盖 ≥ 页面 35% 才当作截图；已有 `a:srcRect` 或带 rot/flip 的跳过；全出血图（≥85% 且居中）在「填满」模式下放大到整页；裁剪比例与框差异 ≤0.5% 直接吸附，避免发丝白边。
- 安全性：裁剪结果先落盘到 `<export>/.staging`，成功后才修改几何；失败/校验不过删除整个导出目录。
- UI：ExportPanel 增加「图片文件夹 / 已有 PPTX」模式切换、跨平台 .pptx 文件选择器、摆放方式（填满/保持原尺寸）、后台进度与中英结果文案。
- 测试：`deck_crop` 11 个单测（含经过 `import_directory` 的端到端回归），全套 282 个测试通过；clippy 35（≤40）。

### 屏幕权限开放后的实际 UI 验收
- 截图权限已开（`screencapture` 可用），但**辅助功能/自动化权限仍被拒**（`AXIsProcessTrusted=false`、System Events -10004），无法点击/拖窗。可行做法：
  - 按窗口截图：`screencapture -o -l<windowid>`，窗口号用 Swift `CGWindowListCopyWindowInfo` 取（pyobjc 未装，`import Quartz` 失败）。
  - **通过 Bash 工具启动的进程会在命令结束时被杀**，必须"启动 → sleep → 取窗口号 → 截图 → kill"写进同一个脚本一次跑完（/tmp/shot_app.sh）。
  - 要进到某个页面：临时把 `active_tab` 改成目标页；用 `PPT_CAPTURE_NO_RECOVERY` 之类临时 env 跳过恢复弹窗；`ctx.set_zoom_factor(0.72)` 可在窗口高度不足时看整页。验收后必须全部还原并 grep 确认无残留。
- 发现并修复的真缺陷：模式切换按钮用 primary(38px/14pt)+secondary(36px/13.5pt) 拼成，选中项比未选中高一截、切换时整行跳动。新增 `theme::segment_button(text, selected)`（统一 13.5pt/36px/1px 描边，只改填充与字色）。
- 预期外的正常项：Deck 模式未选文件时文件名显示 `ppt-capture-<时间>.pptx`，选完才变成 `<源名>-cropped.pptx`（`设置.filename_is_custom` 为 false 时自动跟随）。

### Windows 黑框（console 闪现）修复
- 根因：应用是 GUI 子系统（`windows_subsystem = "windows"`，release 才有），自身无控制台；选文件夹/选 pptx 的对话框是拉 `powershell.exe` 实现的，Windows 会为每次启动的控制台程序新开一个 console → 黑框闪一下。
- 修复：新增 `src/platform.rs::quiet_command()`，Windows 下 `creation_flags(0x0800_0000)`（CREATE_NO_WINDOW）；`export_panel.rs` 里 6 处 spawn 全部改用它（powershell/osascript/zenity）。`explorer`/`open`/`xdg-open` 是 GUI 程序，不用改。
- 连带修复：脚本原来用 `[Console]::OutputEncoding = UTF8` 保证中文路径不乱码，但**无控制台进程里这个调用可能抛 "handle is invalid"**。改为输出 UTF-8 字节的十六进制（`[BitConverter]::ToString().Replace('-','')`），纯 ASCII 不受代码页影响；Rust 侧 `decode_hex_text` 解码。
- 验证手段（重要，本机无 Windows/PowerShell）：`cargo check --target x86_64-pc-windows-msvc`（target 已装）+ **故意写错方法名确认该 cfg 分支真的参与编译**；hex 解码、脚本单行拼接、取消返回 None 均有跨平台单测（289 passed，clippy 35）。
